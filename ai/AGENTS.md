# AI 작업 규칙

저장소 루트의 AGENTS.md와 Git 컨벤션을 따르며, AI 작업에는 다음 규칙을 추가로 적용한다.

## 작업 범위

- 구현·테스트·AI 사용 문서는 ai 폴더 안에서만 변경한다.
- 개인 기획·백로그·진행 상태 문서는 Git에 등록하지 않는다. 작업 상태는 Jira에서 관리한다.

## 브랜치와 커밋

- 1 Story = 1 Branch = 1 MR을 유지한다. Story의 Task마다 별도 브랜치를 만들지 않는다.
- 기본은 1 Task = 1 Commit이다. 다만 구현 범위가 커져 한 번에 리뷰하기 어렵거나 독립적으로 검증할 수 있는 변경이 여러 개라면, 같은 Task를 여러 커밋으로 나눈다.
- 분할 기준은 파일 수나 줄 수만이 아니라 변경 목적과 검증 가능성이다. 각 커밋은 논리적으로 완결되어야 하며 필요한 코드·테스트·사용 문서를 함께 포함한다.
- 구현과 그 구현에 필요한 기본 테스트를 기계적으로 분리하지 않는다. 중간 커밋이 실행·테스트를 깨뜨리지 않도록 의존 순서대로 작성한다.
- 분할한 커밋도 각각 해당 Task의 Jira 키를 대괄호로 포함한다. 예: `feat: [S15P21A207-228] FDS 입력 데이터 계약 구현`.
- 커밋 메시지는 타입, 대괄호로 감싼 Jira 키, 한글 명사형 제목 한 줄로 작성한다. 커밋 전에 예정 메시지와 분할 단위를 사용자에게 보여준다.
- 구현과 검증을 마친 작업은 사용자가 별도로 요청하지 않아도 자동으로 커밋한다. 커밋 메시지·분할 단위를 먼저 알리는 절차는 유지한다.
- Story 병합은 기존 MR·Squash Merge 규칙을 따른다. 커밋을 나누더라도 Story의 작업 범위를 확대하지 않는다.
